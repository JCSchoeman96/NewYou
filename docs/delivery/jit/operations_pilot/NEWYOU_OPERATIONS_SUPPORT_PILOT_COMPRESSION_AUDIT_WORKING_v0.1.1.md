## 3. v0.1.1 hardening corrections

### CORR-08 — Plan pre-first-fulfilment semantics restored
Restored the same-right/no-second-purchase rule, latest-lawful-intent-wins rule, stale-candidate non-deliverability, one-first-fulfilment invariant, display-only distinction, Temperament-profile distinction and post-delivery re-personalisation boundary.

### CORR-09 — consequential command/state dimensions restored
Restored unknown-outcome reconciliation; separate work, command-attempt, source, provider and communication state; and distinct consequential command verbs.

### CORR-10 — pilot counted-admission meaning restored
Restored pilot-qualified production access as the count boundary, participant-centric exactly-once count, reservation semantics, and the rule that ambiguous payment neither counts nor silently recycles capacity.

### CORR-11 — export/deletion lifecycle distinctions restored
Restored as-of snapshot semantics, narrow pre-execution verified export path despite normal access revocation, platform delivery-capability deletion, deterministic inclusion semantics and restore/replay protection.

### CORR-12 — acceleration wording corrected
Removed language implying Redis/ETS/GenServer is a free JIT choice. Current pilot evidence prefers the simplest PostgreSQL-authoritative path and does not justify additional admission authority/acceleration mechanisms.

### CORR-13 — OPS-UPD-003 routing corrected
The authority doctrine is working-converged. Exact command/role/approval matrix remains principally FP-006 JIT/operating-policy work; promote only actual Product/clinical/privacy/security power changes.
