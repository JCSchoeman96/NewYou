# 2. Final cross-decision sweep result

## 2.1 Internal semantic consistency

The sweep found **no material contradiction among `AT-WD-001...019` themselves**.

The accepted model composes coherently as one lifecycle:

```text
valid current entitlement / allowed replacement or remediation
→ first durably accepted scored answer
→ one active attempt + pinned governed execution context + fixed 30-day lifetime
→ conflict-safe resumable answer writes
→ authoritative final-submission acceptance freezes one exact coherent snapshot
→ deterministic scoring under the pinned methodology
→ exactly one canonical immutable result
→ explicit correction/invalidation successors where required, never historical rewrite
→ governed immutable report snapshot(s)
→ explicit participant-selected current profile among eligible sources
→ downstream low-risk personalisation with source provenance
```

Cross-cutting rules remain coherent:

- Entitlements owns commercial right truth; Temperament owns attempt/result truth.
- Identity & Access owns canonical participant reconciliation; Temperament consumes the reconciliation outcome without becoming identity authority.
- Privacy & Consent deletion authority can remove retained immutable assessment evidence; immutability is not perpetual retention.
- Communications owns reminder/delivery evidence, never attempt expiry or assessment completion truth.
- Content & Media owns governed copy/translation publication, never methodology truth.
- Research/Feedback and Interactive Tool outputs remain non-authoritative for Temperament unless an explicit Temperament-owned declaration action creates a declared profile.
- Methodology approval, operator publication, Product application and Health/Clinical authority remain distinct.

No accepted working decision requires a new Domain, shared-write owner, Redis/ETS/GenServer authority, service split or other speculative infrastructure.

## 2.2 Architecture compatibility

Current FLOW-03 already preserves the core architecture needed by the accepted model:

- durable resumable attempt;
- authoritative final-submit completeness validation;
- fixed methodology/version inputs;
- deterministic scoring;
- immutable answers/scores/version;
- duplicate-submit idempotency/uniqueness;
- report retry without rescoring;
- explicit correction/recalculation supersession evidence;
- exact result/content/language provenance.

The accepted Pre-JIT decisions refine Product/Domain/JIT semantics around that path; they do not require a competing architecture mechanism.

# 3. Upstream changes required before governed FP-003 contract completion

The final sweep confirms the following upstream/cross-domain deltas. These are not optional implementation preferences. A lower-level FP-003/JIT artifact may not silently repair them.

## AT-UPD-001 — Align assessment-credit consumption authority

**Status:** `PRODUCT + ROADMAP CORRECTION REQUIRED`

Current locked `DEC-055` says the assessment entitlement is consumed when the first answer is saved / the attempt begins.

Current Product matrices and Roadmap FP-003 still contain conflicting language that the included assessment credit remains unused or is consumed only after successful assessment delivery. The commercial-reversal matrix also contains a technical-failure path phrased as preserving an `unconsumed` right until success/replacement, which is unsafe if applied to an attempt that already crossed the first-answer consumption boundary.

Required correction direction:

- first durably accepted scored answer is the commercial assessment-right consumption boundary;
- attempt commitment/consumption must reconcile with Entitlements idempotently;
- result/report delivery remains a separate fulfilment obligation;
- genuine technical recovery uses explicit recovery/replacement semantics rather than pretending the already-consumed original right was never consumed;
- Roadmap FP-003 exit wording must align with Product Law rather than reintroducing successful-delivery consumption.

This preserves `AT-WD-001...003`, `AT-WD-006` and the current DEC-055 direction.

### Domain wording refinement within AT-UPD-001

Current Domain Map detailed Temperament wording includes `attempt consumption state`, while the ownership matrix correctly makes Entitlements the COMMAND owner of access redemption/consumable credit.

The downstream contract must interpret Temperament's wording narrowly as local attempt commitment/lifecycle state only. A future Domain Law hygiene correction should prefer wording such as `attempt commitment/lifecycle state` or explicitly state that commercial credit consumption remains Entitlements truth. No shared-write authority is permitted.

## AT-UPD-002 — Align Temperament methodology-authority wording to DEC-309

**Status:** `DOMAIN LAW CORRECTION REQUIRED`

Current Domain Map's detailed Temperament profile still says methodology authority is restricted to Venessa/Super Admin under the IP agreement.

Current Product Law/DEC-309 instead establishes methodology authority through the governing IP agreement, with material methodology changes requiring Lynette Beer or another explicitly delegated authority, and explicitly states that Super Admin alone grants no methodology authority.

Required correction direction: retain Temperament as owner of methodology representation, but replace the stale fixed-role authority wording with the current DEC-309/IP-agreement authority model. No Domain ownership move is required.

## AT-UPD-003 — Formalise subscription initial-assessment fulfilment semantics before activating that offer

**Status:** `PRODUCT / ENTITLEMENTS FORMALISATION REQUIRED WHEN IN SCOPE`

`AT-WD-005`/`AT-WD-010` define the accepted discovery model for a qualifying subscription that promises an included initial completed digital assessment: ordinary incomplete expiry does not fulfil that promise; while the subscription remains eligible/unfulfilled, a later replacement attempt may start; one successful qualifying completion closes the initial benefit.

Current MVP authority primarily describes standalone/bundle assessment credits and does not yet clearly establish this subscription-completion promise.

Required direction: if/when a subscription offer includes that promise, Product/Entitlements authority must explicitly encode it before the offer/FP branch is activated. This is not permission for FP-003 to invent a launch subscription benefit.

It is not a blocker for the current standalone/bundle-only MVP path if that subscription promise is not activated there.

## AT-UPD-004 — Add Product-law result correction/invalidation/supersession semantics

**Status:** `PRODUCT LAW CORRECTION REQUIRED`

Current Product Law establishes immutable raw results and reviewed interpretation, while Architecture FLOW-03 permits explicit correction/recalculation supersession evidence. Product Law does not yet fully define:

- deterministic correction of a platform computation defect;
- material methodology invalidation;
- superseded-for-use versus historical preservation;
- current-profile eligibility consequences;
- participant remediation/notification.

Required direction: formalise the `AT-WD-012` append-only correction/invalidation model at Product authority before FP-003 claims that capability. Architecture evidence must not be used to create missing Product semantics.

## AT-UPD-005 — Route OQ-017 to FP-003 for mandatory assessment-expiry warning

**Status:** `ROADMAP ROUTING CORRECTION REQUIRED`

`DEC-056` already requires unfinished attempts to expire after 30 days **with advance warning**. `OQ-017` is the current Reminder Delivery Design gate governing channels, scheduling, retries, quiet hours, observability and rate limits.

Current Roadmap routes OQ-017 only to later packs (`FP-008`, `FP-009`, `FP-013`, `FP-014`) and says it is required before reminder/scheduled-notification promises. That misses FP-003's existing assessment-expiry warning obligation.

Required correction direction: add FP-003 as an earliest relevant OQ-017 consumer for the bounded assessment-expiry-warning path. Do not thereby pull unrelated programme/membership reminder capability into FP-003.

The exact assessment cadence/channel contract may remain FP-003/Communications/JIT configuration under the governing Product and OQ-017 boundaries.

## AT-UPD-006 — Define cross-domain identity-reconciliation consequences

**Status:** `CROSS-DOMAIN JIT/CONTRACT FORMALISATION REQUIRED`

Architecture already requires duplicate-identity merge to be governed reconciliation rather than destructive row collapse. FP-003 still needs an explicit owner-mediated contract covering:

- authoritative reconciliation input from Identity & Access;
- original producing-account provenance;
- dual-active-attempt resolution without answer merging;
- conflicting current-profile selection;
- reconciled completed-result history and reassessment timing;
- Entitlements-owned right reconciliation;
- purchaser/recipient separation;
- deletion/non-resurrection;
- repair if a reconciliation is later proven wrong.

Temperament must not become an identity-matching or entitlement-merging authority.

## AT-UPD-007 — Define the ordinary annual reassessment interval anchor in Product Law

**Status:** `PRODUCT LAW CORRECTION REQUIRED`

Current `DEC-034` says only: no more than one assessment retake per year when a valid entitlement exists. Product §21R.5 separately recognises an annual-use interval and distinguishes it from purchase eligibility, unused credit, completed attempt and Premium annual credit, but does not define the interval's temporal anchor.

That leaves materially different Product outcomes possible: calendar-year reset, subscription anniversary, report date, result-persistence date, or rolling interval from participant completion.

Required correction direction per accepted `AT-WD-014`:

- ordinary reassessment uses a rolling 12-month interval;
- anchor it to the authoritative final-submission acceptance timestamp of the most recent qualifying completed valid digital assessment once that submission has converged to one canonical valid result;
- prevent ordinary reassessment attempt start before the interval opens;
- incomplete/expired attempts, report timing, profile selection and deterministic corrective recalculation do not reset the interval;
- technical/methodology-defect remediation is not an ordinary retake and follows its separate recovery authority;
- Premium entitlement availability remains a separate gate and does not override the ordinary interval.

This is Product meaning and may not be invented solely in a JIT schema/action design.
