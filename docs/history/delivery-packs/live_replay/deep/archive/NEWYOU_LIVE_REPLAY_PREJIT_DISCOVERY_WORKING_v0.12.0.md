# 4. Cross-dimensional convergence doctrine

## 4.1 There is no hidden global owner

No new `LiveJourney`, `LiveOrchestrator`, `SessionCoordinator`, `ReplayWorkflow`, `LiveSaga`, `LiveState` or shared-write Domain is justified merely because FP-007 crosses several owners.

Each durable business truth remains committed by its sole owning Domain.

Cross-domain effects use owner-mediated reads/commands and durable consequences where required.

## 4.2 Coherence does not require one giant distributed transaction

The platform does not need one ACID transaction spanning Events & Live, Entitlements, Content & Media, Privacy & Consent and Communications.

Instead:

1. the authoritative owner commits the smallest coherent durable transition;
2. any must-not-lose downstream consequence is established through the approved durable-consequence pattern;
3. consumers re-read current owning authority before consequential work;
4. duplicate/reordered work is expected and repeat-safe;
5. provider observations reconcile into owner decisions rather than becoming authority;
6. stale projections/messages/capabilities cannot recreate superseded authority.

Exact handoff topology remains JIT because the architecture permits more than one correct representation.

## 4.3 Source-currentness dominates downstream lag

A lagging:

- provider dashboard;
- delivery message;
- signed URL;
- PubSub event;
- Analytics projection;
- Audit projection;
- search/read model;
- cached provider/media status

never overrides current authoritative owner state.

## 4.4 Irreversible external work is handled as evidence/reconciliation

Where a provider call may already have happened, NewYou cannot pretend it did not. The platform must:

- preserve the source business transition;
- preserve external-operation evidence;
- avoid multiplying irreversible effects under ambiguity;
- reconcile safely;
- deny current access/publication when current authority no longer permits it.

## 4.5 Fail closed at authority conflict

When two current owner dimensions conflict, the safest current-authority result wins rather than the most permissive stale result.

Examples:

- registration valid + entitlement revoked => no new access capability;
- provider recording ready + Privacy purpose withdrawn => no automatic replay publication;
- replay V1 provider URL works + C&M V1 withdrawn => no current delivery authority;
- old cancellation/reschedule email says one thing + current Events occurrence says another => Events truth wins;
- deletion in progress + queued message not yet admitted to provider => revalidate current Privacy/source authority before provider I/O.
